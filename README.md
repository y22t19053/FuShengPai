🃏 浮生牌 · FuShengPai
一面镜子，不是一盏灯。

浮生牌是一个开源的、基于扑克牌的决策辅助工具。

随手打开，抽一副牌，得到一点启发。

不装神弄鬼，不搞宗教，不做心理测试，不说废话。

📖 它是什么

你有个烦心事。

不知道怎么选，或者心里其实已经有答案了，只是不敢承认。

打开浮生牌——输入问题，抽牌，布阵，看解读。

仅此而已。

它只是一个网页。

不是 app，不是 exe，不需要安装，不收集任何数据。

你愿意，可以只用本地引擎；你想深入，可以接自己的 AI Key，或者复制提示词发给任意 AI。

它最像的参照物，是网络上一二十块钱给你抽牌的塔罗占卜师。

只不过那个行业骗子太多，而我们是一面镜子。

善易者不卜——但人总需要做决策。

使用浮生牌，不是迷信它，而是相信自己的能力。

浮生牌存在的意义，不是告诉你“会发生什么”，

而是提醒你“你自己其实知道该怎么选”。

🗡️ 文案标准

浮生牌的解读文案，遵守以下原则：

不讲古词。你说一句用户听不懂的话，等于放屁。

不装逼。“官鬼持世，此事忧疑”——占卜师自己说不清楚才拽这些。

不扒用户。“你表面坚强但内心柔软”——这种巴纳姆效应的屁话，用户会觉得被冒犯。

不搞“缺少一个机会就会出头”的鸡汤——纯放屁。

该给的情绪价值还是得给。

即使是一个工具，也不能冷冰冰。

心理层面的承接不是骗人，是让人觉得自己被看见了。

解读本身有个固定骨架，一直在用：

先说结论，一句话，不铺垫。

把牌翻成一个能看见的画面——水龙头、马达、屋顶、水里的腿。翻不出画面就不说。

说成因，落到现实：时间、钱、身体、身边那个人。

归因一句：这不是你一个人的问题，或者这是你选的。二选一，必须有一句。

给一个今天能做的小动作，只给一个。

最后把决定权还回去——走哪条路，你自己定。这一句不能省。

坏消息也要四层说完：结论、归因在外、一个画面、留一线。不吓人，也不说成注定。

❓ 怎么问

同一个问题，问法不同，答案的质量差很多。

两条路一起问——“我走 A 还是走 B”——你拿到的会是两条路的平均数。

所以先把问题收窄成一条路，再补三样东西：

一个时间点：三个月内、年底、明年六月。

一个数：三万、三百万、一周两次。

一个能判真假的形态：不是“顺不顺”，是“能不能成”。

写完读一遍：“我要问的是不是……”，确认没走样，再抽。

不知道自己问得对不对？占卜台上有「感觉自己没问清楚？」——它会读一遍你写的那句，指出哪里会打折，并给几组改写对照。

同一件事不必天天问。七天内问到同一个问题，开头会先提醒一句“这个你刚问过”，然后照样给你解读。想换个时间点再问，十天后再来。原因是：牌没变，变的是你还没准备好接受它；反复问，答案只会越来越像你希望的那个。

🖤 再看一层

每份解读最后有一段「再看一层」。它不下新结论，只把这件事翻个面：

如果反过来看会怎样。如果真成了，代价是什么。这里面哪一块其实不是你的。

读得快的人容易跳过它——通常跳过的人，会在三天后又来问同一个问题。

🚫 有些问题不接

寿命、生死、别人的心思、赌运、医疗诊断——这几类不看。

不是装清高，是这类问题问了对你没好处。

拒绝时会说明为什么，再给一条能正面回答的替代问法，不会丢一个“不答”就走。

🎲 关于随机

浮生牌最底层的坚持：杜绝伪随机。

我极度反感那种“点按钮瞬间在代码库里随机生成结果”的占卜方式。

那不是抽牌，那是函数调用。

浮生牌要做到的是：在最大程度上模拟现实中的出牌。

牌局具有现实可复刻性——

两个平行世界里，一个人抽实体牌，一个人用浮生牌，抽出的牌完全一致。

你选哪一张，比随机更重要。

⚖️ 张力指数

张力指数，一句话定义：这局牌的拉扯程度。

原则上来讲，玄学是不能量化的。

但总有人喜欢看数值，就像总有人喜欢问“甩棍和匕首对打哪个能赢”。

这种东西不该影响产品的判断，但你给它一个数值，反而能避免很多麻烦。

张力指数就是那个按钮——

它不替你做决定，只把牌局里的松紧、冲突与节奏，换算成一个能读懂的数字。

（曾用名“榴莲指数”，因图形过于猎奇已移除；数值与色条沿用，文案已收敛。）

接入 AI

浮生牌支持三种使用方式：

外接你自己的 AI API（在设置中填入 Key 即可）

用自己机器上的 Ollama / LM Studio，不用 Key、不花钱、推理不出本机

复制提示词，粘贴到任意 AI 工具

Key 只存储在你的浏览器本地，不上传任何服务器。

🖥️ 用本机模型跑（不用 Key，不花钱）

机器够用的话，整套解读可以完全跑在自己电脑上。Ollama 或 LM Studio 都行，只要它对外开放的是一个 OpenAI 兼容接口。

装好 Ollama 之后拉一个模型（8G 显存，8B 四比特量化够用）：

Bash
ollama pull qwen3:8b

自检脚本会照浮生牌的真实请求打一遍，把耗时和坑直接告诉你：

Bash
node scripts/check-local-model.mjs
node scripts/check-local-model.mjs http://127.0.0.1:11434/v1 qwen3:8b

然后打开浮生牌 → AI 设置 → 选「本机 Ollama」，Key 留空，模型名填 qwen3:8b，点「测试连接」。

服务已经在跑了但不记得模型叫什么？点「🔍 检测本机模型」，它会把服务里的模型直接铺成一排按钮，点哪个填哪个。

几件踩过的坑，写出来省你时间：

推理型模型（qwen3、deepseek-r1 这类）默认先把回答“想”一遍再吐正文，小模型上这一步能耗掉二三十秒，甚至把输出预算全吃光、正文一个字都没有。浮生牌遇到“只有思考没有正文”会自动关掉思考重试一次（reasoning_effort: none，配 /no_think 兜底）；地址是本机的，第一次就直接关。

第一次请求要加载模型（4~5GB 的量化模型，机械盘上可能等一分多钟）。加载完之后同一个模型基本 1~4 秒出结果。`ollama ps` 能看到它是否还驻留在显存里。

ComfyUI 这类出图服务常驻会占掉好几个 G 显存，让 Ollama 退回 CPU 跑，慢一个数量级。切到占卜之前先把出图服务停掉。

同一局域网里另一台机器跑 Ollama 也行：那台用 OLLAMA_HOST=0.0.0.0 启动，这边地址填 http://192.168.x.x:11434/v1，同样不用 Key。

显存参考（实测：RTX 4060 8G + qwen3-8b 四比特量化）：一句话日运约 1.5 秒，一段两百字上下的完整解读约 3~4 秒。

🧿 对读模式（占卜师版）

给在线接单的塔罗师/占卜师用的「信任工具」，不是新的占卜玩法。

- 客户自己抽牌：占卜师建房间 → 生成链接/二维码 → 客户在自己手机上抽牌，占卜师无法预设或替换
- 凭证复现：客户把「牌局凭证」发回，占卜师输入同一凭证，看到一模一样的牌局与结构事实（体用/五行/宜忌）
- 对读回执：双方各持一份凭证，占卜师补充人的解读，一键复制回执发给客户
- 展示分档：A 只给牌面+宜忌 / B 加结构摘要（推荐）/ C 完整结构解读，由占卜师决定
- 立场：我们验证牌面，不验证命运；不做预测承诺

入口：dual.html（占卜师版落地页；带 ?room= 参数即客户视角；?receipt=demo 看回执海报）。

能力：
- **两种牌**：扑克牌（浮生牌体系，站点给五行/体用结构）+ 塔罗牌（78 张、三张牌、正逆位；站点只记录牌面，不解读，解读由占卜师说）
- **对读回执海报**：1080×1440 PNG，含牌面/凭证/时间锚定/占卜师解读；占卜师端与客户端都能一键保存，落款写你自己的名字
- **时间锚定**：可选 Cloudflare Worker（server/），把凭证指纹钉到服务端时间；未配置自动退化为本地记录
- **没有收费档位**：不用卡密、不用注册、没有会员。建房间、复现、回执、换落款，全部直接可用
